Core App Design System

Introduction

This design guide provides a comprehensive reference for using the Core App Design System. It showcases all available components, their variants, and usage guidelines to ensure consistent design across the application.

Getting Started

To use the Core App Design System in your project, you'll need to include the following resources. Add these to the <head> section of your HTML document.

Required Resources

1. CSS Stylesheet

View and copy our global styles to your project:

open_in_new View global-styles.css
<link rel="stylesheet" href="global-styles.css">

2. Font Family

We use Work Sans as our primary font family:

<link href="https://fonts.googleapis.com/css2?family=Work+Sans:wght@400;500;600&display=swap" rel="stylesheet">

3. Material Icons

Include Material Icons and Symbols:

<link href="https://fonts.googleapis.com/icon?family=Material+Icons" rel="stylesheet">
<link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Material+Symbols+Outlined:opsz,wght,FILL,GRAD@20..48,100..700,0..1,-50..200">

4. Material Web Components

Include the Material Web Components library for interactive elements:

<script type="module" src="https://unpkg.com/@material/web/all.js?module"></script>
Note: For production environments, consider hosting the CSS and fonts locally to improve performance and ensure availability.

Usage Guidelines

Form Layout Best Practices

  • Use required-marker-asterisk class for required fields
  • Group related form fields with clear section headings
  • Maintain consistent spacing between form elements (recommended: 20px)
  • Use field-label class for all form labels

Button Usage

  • Use filled buttons for primary actions
  • Use outlined buttons for secondary actions
  • Use text buttons for tertiary actions
  • Use small-btn class when buttons need to fit in compact spaces

Accessibility Best Practices

  • Ensure all interactive elements are keyboard navigable
  • Maintain color contrast ratios of at least 4.5:1 for text
  • Provide appropriate ARIA labels for complex widgets
  • Use semantic HTML elements whenever possible

Responsive Design

  • Forms should stack vertically on mobile screens
  • Use the small-btn class for buttons on mobile interfaces
  • Consider using a single-column layout for forms on screens smaller than 768px
